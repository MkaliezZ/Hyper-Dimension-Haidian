# 本机完整校园接入：标准容器操作方案

本方案替代已弃用的 Windows 自动启停封装。原杀毒告警及删除受阻记录保留在 `evidence/native-connection-20261030/SECURITY-HOLD.md`。

## 安全审查决定

1. 不恢复 `native-campus.ps1`，不执行同批 rollback/import 助手，不改名、换解释器或设置杀毒例外。构建上下文显式排除未审查的 `scripts/import-local-visitor.mjs`，`.local` 原本即被排除。
2. 使用直接、可见的 WSL Ubuntu 终端与标准 Docker Compose 命令。开发时以前台 `docker compose up` 持有服务会话；不创建隐藏 Windows 进程、保活脚本、计划任务或额外网络加载器。
3. Hermes 凭据使用已准备的 Linux 私有配置和 Docker secret 挂载。启动、回滚与健康检查都不把模型密钥读到 Windows JavaScript、命令行参数、日志或源码。
4. 访客身份的 `access.json` 与 `state.json` 作为私有迁移输入，只经文件复制进入新 runtime 卷。原目录和新备份均保留，不通过浏览器获取用户 Cookie，不为既有用户伪造身份。
5. 数据导入只调用封存 Base 已有的 `tools/m1-import-json.mjs`，要求旧写入者已停止、目标运行状态为空、先做校验备份。完整字段摘要、原件哈希、访客形象/位置/会话数量均须核对。目标已有运行状态则停止，不覆盖。
6. 当前公开预览只通过既有本机控制通道正常停止。若该操作被审批拒绝，保留现场，不改用进程强杀或另一工具绕过。
7. 原生服务先在 Linux 回环地址验证，再检查 Windows 4190 的实际健康状态。未确认 `nativeCampus:true`、`schoolId:uw` 和正式身份授权前，不宣称页面已完成接入。

## 当前目标

本机固定单学校 `uw / uw-seattle`；负责人和学生使用明确标注的开发账号。真实邮件、域名及机构身份按部署手册单独配置。原用户访客存档保留，访客与账号不相互覆盖；不自动把接待私有会话加入知识库。

全部 22 个功能入口按四个 Base 归类，负责人专用入口继续检查当前角色，业务 API 保持原有权限检查。活动、合作等业务的实际校方资料和外部履约配置仍由部署方填写。
