# 四个 Base 的 UW 场景接入 · 2026-10-30

本次是现有 UW 开发副本的功能迭代。通用 Base 和封存交付包继续保留，没有生成新 ZIP。

## 当前入口

正文与常用按钮调至 14–16px，辅助信息及地图标记主要为 12–13px。360/390px 窄屏使用两行顶部操作栏；接待输入为 16px，人物编辑保存区保持可见。地图尺度与人物贴图尺寸沿用当前版本。

“校园服务”按以下四组筛选，地标卡片可以直接进入 Base 2 或 Base 3：

| 板块 | 已有能力和本轮入口 |
| --- | --- |
| Base 1 · 空间与接待 | 当前地图接待、独立会话、正式账号和学校权限、地点服务与反馈 |
| Base 2 · 人物与生活 | 地图形象编辑、背包与纪念、同意后的联系人与私信 |
| Base 3 · 社区与运营 | 地点论坛、校园活动、贡献排名、校友/学长/机会、学生会运营 |
| Base 4 · 周边合作 | 同一学校内的合作服务目录、授权工单与权益 |

所有业务入口由后端重新检查账号、学校、模块开关和地点绑定。论坛、背包、校友支持与空间反馈支持地点参数；活动、排名和合作服务目前打开全校入口。接待可以在公开参观模式直接打开。未连接、未登录和学校未启用分别显示对应状态。

## 本轮修复

原学校副本的 `base/src/platform/environment.mjs` 中，户外地点适配函数与内部查询函数重名，地点反馈请求会错误调用内部函数。本次给导入函数使用独立名称，恢复户外地点枚举。新增行为回归覆盖地点筛选、负责人分配权限、学生权限与非成员拒绝。

修改仅进入 UW 学校副本；同步了该副本的载荷摘要，原 `SEALED-BASE-MANIFEST.json`、公共 Base 源码与旧交付仍保留。

## 实际验证

- 当前源码 69 项回归通过，81 对地标路线与原 GIS 几何摘要通过。
- 隔离浏览器在 1440、768、390、360 宽度检查字号、顶部布局、接待、形象保存区与四个 Base 的筛选。地标卡片传递地点并打开指定板块。
- 新建独立 Ubuntu 测试实例 `uw-readable-base-20261030`，使用虚构学校账号与独立数据库卷。沿用本机固定依赖镜像，挂载当前学校源码与修复文件只读验证；不是本轮重建的生产镜像。
- 8 项真实原生检查通过：Keycloak 登录及 UW 成员身份、11 个业务模块状态、地图到 Base 3、后端授权与地点链接、论坛地点筛选、空间反馈与角色权限、背包地点选择、合作目录及未登录拒绝。具体分组见 `evidence/readable-base-entry-20261030/native-result.json`。
- 学校副本保护审计通过，64 条保护记录未改变。此前 9 项全业务与 8 项恢复验收仍是历史证据；本轮没有重新调用模型、发送消息、计分或执行备份恢复。

## 后续开发顺序

1. 把完整校园模式接到持续使用的开发入口，核对负责人、学生与访客身份切换和账号人物恢复。保留现有访客存档，先确认实际数据迁移范围。
2. 以当前地图地点为上下文，继续验收 Base 2 的到达判断、背包与非破坏性互动。
3. 接入学校审核后的活动、论坛运营、贡献规则和负责人工作台，串联 Base 3 的提交、审核与计分。
4. 接入学校批准的合作方资料和业务 Agent，逐项核对 Base 4 的授权、工单和权益回执。

当前 4190 预览仍是公开参观模式；本轮完整业务验证在隔离的 6390 实例进行，测试后停止并清理。现有用户数据和预览配置未切换到虚构测试学校。启动正式完整模式仍按 [DEPLOY-UW](DEPLOY-UW.md) 操作。
