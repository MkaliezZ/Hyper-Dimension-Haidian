# 人物素材库扩充与旧存档兼容

## 已实现的素材范围

`campus-original-2` 是独立的第二版素材库，共 38 个部件条目；“无眼镜”和“无配饰”分别占一个条目。它满足四 Base 规划的人物库最低数量，并沿用 `campus-humanoid-1` 骨架和 Idle、Walk、Wave 动画。

| 分类 | 实际款式数 | 说明                                       |
| ---- | ---------: | ------------------------------------------ |
| 体型 |          3 | 标准、纤细、宽肩；另可选身高和轮廓表现     |
| 发型 |          8 | 新增双辫、高丸子头、披肩长发               |
| 上装 |          6 | 新增翻领短袖、开衫、衬衫针织背心           |
| 下装 |          6 | 新增牛仔长裤、工装长裤、宽腿裙裤           |
| 鞋子 |          4 | 新增圆头短靴                               |
| 眼镜 |          3 | 新增椭圆金属眼镜；另有“不佩戴”             |
| 配饰 |          6 | 新增耳机、双肩包、发侧蝴蝶结；另有“不佩戴” |

包含校园日常、图书馆的一天、校园轻运动、创作与社团四套预设。素材为本项目原创程序化曲面几何，MIT 授权；没有引入外部人物网格、贴图或肖像。每个部件记录来源、授权、版本、骨架、大小和 SHA-256。人物是风格化校园形象，采用固定骨架和部件绑定；目前不包含布料模拟、面部表情编辑或任意第三方 VRM 导入。

## 用户操作

1. 登录学校账号，打开“我的形象与记忆”页面 `/m2.html`。
2. 在“人物素材库版本”选择“扩充素材 · 38 部件”。此时只预览，不改变存档。
3. 选择预设，或逐项选择部件、肤色、身高、轮廓与颜色；预览站立、行走和挥手。
4. 勾选升级确认，再点击“确认升级并保存形象”。未确认时，界面和服务器都拒绝升级。
5. 再次登录、换浏览器上下文或进入学校场景时，读取同一学校账号下保存的配方与模型摘要。

已有存档保持原素材库。新账号也从原版开始，由用户决定是否升级。升级后可继续编辑扩充版；目前没有直接降级入口。旧配方和模型摘要保留在历史记录，旧生成器可以继续重建完全相同的旧模型。预览时切回当前已保存版本或点击“恢复已保存形象”，可放弃尚未保存的编辑。

## 版本和接口契约

| 项目               | 原版                | 扩充版                |
| ------------------ | ------------------- | --------------------- |
| `catalogVersion`   | `campus-original-1` | `campus-original-2`   |
| `generatorVersion` | `campus-rig-1.0.0`  | `campus-rig-2.0.0`    |
| 部件条目           | 24                  | 38                    |
| 素材目录           | `assets/avatars/`   | `assets/avatars/v2/`  |
| 公共素材入口       | `/avatar-library/`  | `/avatar-library/v2/` |

原版目录、生成器与部件文件继续保留。`src/avatar/library-m2.mjs` 按配方版本分发到对应生成器，原版模型不会使用新生成器重新解释。第二版代码位于 `src/avatar/catalog-m2-v2.mjs`、`src/avatar/model-m2-v2.mjs`。

- `GET /m2/schools/{schoolId}/avatar` 返回存档及 `availableCatalogs`，不会写入数据库。
- `GET /m2/schools/{schoolId}/avatar/catalog` 默认仍返回原版；`?version=campus-original-2` 获取扩充版。
- `GET .../avatar/model.glb` 按已保存的版本生成；`POST .../avatar/preview` 可重建任一受支持版本。
- `GET .../avatar/history` 保留旧配方、模型摘要和来源；升级记录来源为 `catalog-upgrade:campus-original-1`。
- `POST .../avatar` 继续使用 `requestId`、`expectedVersion`、目标 `catalogHash` 和 `recipe`。跨版本时额外提交 `upgradeFrom: {catalogVersion, catalogHash, modelHash}`，三项必须与当前存档一致。
- 未确认、旧确认摘要、未知版本、错误部件、部件冲突和降级请求显式失败。两个页面竞争更新时，仅一个版本更新成功，另一个返回 CAS 冲突。同一请求重试返回原回执，不重复写历史。
- 现有 M0 旧存档迁移仍要求 `legacyVersion` 确认，保留 `hd_avatars`。本扩充无需数据库迁移，不改变学校/用户权限边界。

原版目录摘要为 `945bd70c4e68f3e63f61b6ad82e3b5994539cd4096dde97181b9b7926a3a9ba0`；扩充版为 `459620abf448d6f5d4f1c13c2e481b53cb836b22b1325dfd6bfaafd581fca204`。后续修改已交付的几何应增加新版本，不能覆盖旧生成器或旧资产。

## 兼容性与预算

每个完整模型最多 22,000 个三角面、90 个绘制批次、1,600,000 字节。测试同时检查单个新部件组成的完整人物、四套预设，以及各槽位几何最高值相加的保守三角面上界。

在原版限制上，扩充版增加：丸子头与帽子/耳机、蓬松卷发与耳机、披肩长发与背包、卫衣帽领与背包不能组合。界面显示冲突，服务器拒绝保存，不偷偷替换部件。真实美术扩展仍需逐组合检查，现有自动预算验证不代表所有视觉组合都经过真人评审。

## 可复现生成与验证

在项目根目录执行：

```sh
# 只核验已有原版部件，不重写原版文件。
node tools/m2-assets.mjs --version=campus-original-1
# 核验原版后，仅生成 assets/avatars/v2；默认也是此扩充版本。
node tools/m2-assets.mjs --version=campus-original-2
node --test tests/m2.test.mjs tests/avatar-extension.test.mjs
```

在线链路验证必须使用独立的演示数据库、服务和虚构测试账号，设置 `HD_M1_TEST_FIXTURE=1` 后运行 `tests/avatar-extension-live.mjs`。它创建专用测试用户，不升级日常或既有验收用户的存档，并生成被忽略的 `.local/avatar-extension-qa-users.json` 供浏览器测试使用。不要将该文件、私密配置、会话或密钥收入交付包。

浏览器测试为 `tests/avatar-extension-browser.mjs`；设置上述隔离配置、专用用户文件与 `HD_QA_CHROME`，使用全新自动化上下文。每轮需要 live 脚本新建的原版存档，因为浏览器验收会明确升级该专用用户。

本次隔离验收记录位于 `qa/avatar-extension/live.json`、`browser.json`，截图为 `studio-v2.png`、`scene-v2.png`：原版哈希和全部旧资产不变、38 部件路径完整、拒绝隐式升级、并发版本保护、重试、独立登录/浏览器恢复、运行场景加载一致模型均通过。它们是同一主机上的自动化测试，不是物理多设备、真实学生或目标服务器验收。整套六数据库备份恢复由交付总验收单独记录。
