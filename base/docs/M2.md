# M2：人物、存档、背包与轻道具

> **历史范围 / 兼容工具参考。** 本文记录当时里程碑，不是当前完成度或开发优先级。旧的“尚未实现”、功能上限、数据库数量及候选状态不覆盖后续版本；涉及具体命令仍须核对当前脚本和实例。当前流程以[统一开发手册](../DEVELOPMENT-MANUAL.md)及本版验收为准。

当前产品分工：Base提供简单部件编辑、行动与存档；学生会负责自有人物美术。下述既有原创库保留为可运行占位和历史兼容，不再扩充其款式作为默认目标。学校素材接入与验收见 `docs/AVATAR-SCHOOL-ART.md`；任意生成模型仍需骨架及目录适配。

## 1. 成品操作

登录学校账号 → `/m2.html` → 选择当前学校 → 编辑/预览 → 保存 → 领取欢迎背包 → 进入空间 → 选择公开房间 → 点击“前往这个房间” → 抵达后使用道具。再次登录或换浏览器恢复服务端的配方、模型摘要、装备与收藏。

24个原创部件包括3体型、5发型、3上装、3下装、3鞋、3眼镜选项和4配饰选项，含“不戴/不加”项。另有3身高、6肤色、3性别表现轮廓，以及发色、上下装、鞋色。性别表现是外观选项，不推断或收集真实身份。4个完整预设均可编辑。站立、行走、挥手与统一骨架可复用，基础动作由原始 glTF 骨骼动画驱动。

| 道具 | 使用条件与效果 | 持久化/消耗 |
|---|---|---|
| 校园地图 | 装备后收藏当前空间的公开地点 | 每地点只收藏一次；可从收藏页请求正常寻路 |
| 地点明信片相机 | 装备且实际抵达公开房间；可填70字题记 | 每次1张纸；保存地点/几何摘要/当时人物摘要，下载原创 SVG 纪念插画 |
| 集章册 | 装备且实际抵达公开房间 | 每地点1枚，不产生贡献分 |
| 应援小旗 | 装备后触发3秒挥手，3秒冷却 | 留使用记录，仅自己的画面可见 |
| 记忆卡 | 实际抵达公开房间，填写8–500字 | 每次1张；只保存私人草稿，用户可带到论坛编辑器，确认后进入原审核流程 |
| 明信片纸 | 相机的材料 | 欢迎包5张，服务端确认扣减 |

欢迎包每校账号只发放一次：地图、相机、集章册、小旗各1，记忆卡3，纸5。学校负责人可以通过受控 API 追加已定义物品并填写理由；成员、客户端和模型不能自授。道具不改几何、不写他人存档、不自动公开、不生成积分。范围及数量由服务器判断。

## 2. 技术选型与素材约束

- Three.js **0.186.1**：沿用渲染/寻路坐标，不引入第二套场景引擎。
- [pixiv/three-vrm](https://github.com/pixiv/three-vrm) **3.5.4 / MIT**：加载 VRM 1 元数据和人形骨架。代码配方编辑器使用本项目原创几何部件。没有导入第三方人物素材或不明授权贴图。
- [CharacterCreator](https://github.com/webaverse-studios/CharacterCreator) 的现有 package.json 使用较早的 Three/three-vrm 版本及额外 Web3 依赖。本轮不整包集成，采用固定当前加载器与受控部件目录；未宣称实现其全部导入、烘焙或导出能力。
- 身份/学校继续使用 M1 的 Keycloak + PostgreSQL；原始聊天仍归 Nakama、论坛归 NodeBB。人物库存不另建浏览器权威存储。

`assets/avatars/catalog.json` 包含每项作者、来源、MIT授权、版本、骨架、文件摘要、兼容性、四个预设。GLB另含 VRMC_vrm 1.0 meta/humanoid，允许公司使用、修改与再分发；阅读该目录的许可证，分发时保留许可。它们是可运行的原创卡通基础素材，学校最终美术审定仍由学校执行。

预算：完整人物≤22,000三角面、≤90渲染批次、≤1.6MB GLB。模型以骨骼节点的刚性部件构成，非柔性蒙皮衣物模拟；不可声称已支持任意 VRM 模型/动画导入。卷发+帽子、卫衣+围巾有明确兼容性拒绝。旧/未知部件或目录版本冲突不会静默替换。

```bash
npm ci --ignore-scripts
npm run setup
node tools/m2-assets.mjs  # 仅再生成本项目原创建模产物；不是改用户存档
```

模型在服务器确定性重建，以配方、目录/骨架/生成器版本、完整模型摘要确认。目录和已保存模型不符会返回409，保留数据等待显式版本迁移；不能覆盖旧目录冒充无变化。

## 3. Ubuntu 新实例

Node24 LTS、Java21、PostgreSQL与固定服务安装见 docs/M1.md、integrations/versions.json。本包携带 Base生产依赖、浏览器库、原创人物和原中文embedding模型；外部 Keycloak/Nakama/NodeBB/数据库/Java 的发行包仍通过固定安装器获取，并非完全离线镜像。

```bash
npm ci --ignore-scripts
npm run setup
bash tools/m0-install-ubuntu.sh /srv/hd-m2-services
export PATH=/srv/hd-m2-services/node/bin:$PATH
export HD_M1_SMTP_FILE=/secure/school-smtp.json
export HD_M0_PG_ADMIN='<private PostgreSQL initialization connection>'
# 端口示例，先核对本机没有冲突；不要覆盖已有服务目录或库名。
export HD_M1_ORIGIN=http://127.0.0.1:4780
export HD_M1_ISSUER=http://127.0.0.1:8680/realms/hd-m1
export HD_M1_FORUM_PORT=5067
export HD_M1_NAKAMA_PORT=8350
node tools/m2-init.mjs --runtime /srv/hd-m2-services --namespace school_m2
unset HD_M0_PG_ADMIN
export HD_M0_CONFIG=/srv/hd-m2-services/private/config.json
node tools/m0-services.mjs start
```

初始化仍是 `milestone:M1` 以复用正式账号/聊天服务，另设 `m2Enabled:true`。该开关由 m2-init 只写入刚初始化的配置。脚本拒绝已有私有配置/同名数据库；正式实例不使用 `--fixtures`。首次负责人按 docs/M1.md 经受控终端核验并建立；其余账号由负责人邀请。选择学校使用自己的稳定 ID/spaceId，不把示例 north/south当作真实学校。服务启动器打印 READY 后再访问。

## 4. 既有 M1 的安全升级

1. 原源码、ZIP、数据库不覆盖。停写原实例，使用 m1-backup 创建并校验完整备份，然后可恢复原服务。
2. 按 docs/M1.md 恢复到新目录、数据库命名空间及端口，复制固定服务版本；完整校验再绑定新源码。
3. 维护者核对新克隆的路径与命名空间后，在**克隆**私有配置设 `m2Enabled:true`。不要自动更改原现网配置。
4. 使用新源码启动克隆，校验已应用迁移摘要，只追加 m2-001；首次登录后确认旧配方迁移。旧 `hd_avatars` 表不改写，新 `hd_m2_avatars/history` 单独存。
5. 新端口需运行 m1-relocate-client。验证登录、旧聊天和学校隔离，再走人物/背包/恢复验收。
6. 部署方决定何时切换入口。回滚使用保留的旧实例；新实例已经产生的数据应先完整备份，不将新库逆向覆盖旧库。

M2七张表随业务库全量备份，无额外独立库。完整备份仍要停止整套写服务、确认没有数据库客户端、保存私有配置/密钥与学校空间素材。恢复只到新库；不能只复制人物JSON就声称完整恢复。

## 5. HTTP 契约

全部个人路由要求已验证身份、当前本校学校级成员权限；partner/affiliate 不借组织权限进入学校数据。学校、用户由服务器令牌确定，不能用 userId 读取别人存档。请求ID重复且输入改变返回409；版本过时返回409。成功回执与数据同事务提交。常规错误不会扣物品。

前缀 `/m2/schools/{schoolId}`：

| 路由 | 输入/结果 |
|---|---|
| GET `/avatar/catalog` | 当前固定部件、兼容性、预算与目录摘要 |
| GET `/avatar`、`/avatar/history` | 本人配方、版本、模型/目录摘要与旧版迁移状态；本人最近30条历史 |
| POST `/avatar/preview` | 受控完整配方→GLB，不存档、不接受任意URL |
| POST `/avatar` | requestId,expectedVersion,catalogHash,recipe；首次旧版迁移另须legacyVersion |
| GET `/avatar/model.glb` 或 `.vrm?hash=...` | 本人模型；摘要变化/尚未确认旧迁移时409 |
| GET `/inventory`、`/inventory/events` | 数量、装备、revision、物品目录、本人最近100条事件 |
| POST `/inventory/starter` | requestId,expectedRevision；仅一次欢迎包 |
| POST `/inventory/equip` | requestId,expectedRevision,itemId,equipped |
| POST `/inventory/grant` | 仅学校owner：requestId,expectedRevision（目标背包）,userId,itemId,quantity(1–100),reason(3–200字) |
| POST `/inventory/use` | requestId,expectedRevision,itemId,action,sceneId,entityId；note另须text，postcard可附caption |
| GET `/collections`、`/collections/{id}` | 本人最近100条及单条；他人ID返回404 |
| GET `/collections/{id}.svg` | 本人地点明信片下载，输出文字XML转义 |
| GET/POST `/profile` | 自我介绍、院系、年级、兴趣及每字段private/school；写入须requestId/expectedVersion |
| GET `/profiles/{userId}` | 仅本校当前成员，仅返回school可见字段；没有私信/邮箱/私人记忆 |

发放与装备按背包锁+revision，使用道具还在PG运行状态事务中读取实际位置与寻路状态。到达判定不采信客户端坐标。收藏幂等、扣减、回执、使用事件一起提交。预览或模型文字不授予任何权限。公开 `/avatar-library/` 只提供本包的受控原创目录与部件/预设，绝不提供用户模型/图纸/私有文件。

接待知识仍走已发布资料与既有向量数据库；私人名片、道具/位置历史、记忆草稿不会自动embedding或转交模型。学校名片目前提供基础字段和可见范围，不含正式身份认证徽章、作品集或跨校公开名录。
