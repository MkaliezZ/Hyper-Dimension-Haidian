# 当前通用功能与配置边界

当前校园包为 v0.8.3：文档、入口与打包检查整理；应用运行时沿用 v0.8.2。主流程见[统一开发手册](../DEVELOPMENT-MANUAL.md)，本版[文档验收](../evidence/documentation/ACCEPTANCE.md)与先前运行证据分开记录。下文按版本保留功能形成过程，不把旧阶段状态当成新验收。

| Base         | 已实现的通用功能                                                                       | 本轮新增                                                                                      | 实际学校仍要提供                                                      |
| ------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1 空间与接待 | 场景/导航/空间包、协议与 A2A、接待、可选 Hermes/模型、公开资料与 pgvector              | 自动向量队列、发布/撤回即时来源校验、Ubuntu 全栈容器                                          | 本校图纸、正式美术、获准公开资料、域名/SMTP/TLS 与模型配置            |
| 2 人物与关系 | 简单部件搭配、服务端存档、背包轻道具、联系人同意、私信和聊天、个人展示                 | 按年级筛选、自愿个人行动、跨月同主线去重、状态恢复与删除                                      | 本人选择是否适用，不默认让家人参与                                    |
| 3 共创与运营 | 原生论坛、搜索/审核/举报/申诉、地点记忆、活动/志愿、版本规则、贡献排名、受控奖励与复盘 | 私有论坛长期审核历史、学年/年级/渠道运营、版本导入启用、负责人分工/交接、日期核对与活动草稿   | 真实学校日历、具体运营规则/权重、预算、正式负责人、实际需求与效果验证 |
| 4 校外合作   | 申请/审核/目录、工单、明确资料转交同意、回执与对账、受控权益核销                       | 官方 SDK 可调用的合作业务 Agent A2A、限定范围/技能/期限委托、重放/到期/撤销、年度合作工作入口 | 已核准合作方、真实条件、外部接口与实际履约验证                        |

v0.7.1 补齐逐项评级条件、全局适用分支与学生需求独立展示，提供只读来源核对、24 项分页和跨页选择；完整实际材料在隔离组织跑过前后端流程，详见 `docs/ANNUAL-MATERIALS-AUDIT.md`。

信息管理沿用统一学校/组织 ACL、当前身份、来源版本、事务回执、审计、事件与备份。公开接待、私有论坛历史、私信、个人选择与合作方字段授权各有权威来源和范围，不相互自动复制。模型回复和排名都不授予权限。

技术沿用 Node 24、PostgreSQL/pgvector、Keycloak、NodeBB、Nakama、pg-boss、Three.js/VRM、React-admin 和官方 A2A SDK；本轮没有为年度运营再引入第二套账号、论坛、任务队列或向量数据库。Python 标准库只用于只读材料转换，Ubuntu Docker/Compose 提供编排，浏览器为前端。

本轮 v0.8.0 增加接待会话生命周期、本人自愿的校友/成员发现名片、学长/导师支持时段及预约、原生论坛正文与结构化审核共同约束的职业机会。均有页面入口、负责人/管理员操作和公开建筑点位入口，见 `docs/RECEPTION-AND-NETWORK.md` 及 `evidence/network`。个人 Agent 长期记忆已按用户决定从范围移除；接待会话默认30天、学校可配置、本人可导出/删除。支持预约是明确申请确认，不是自动匹配、代约外部会议或职业结果担保。

P1 的论坛审核历史索引已补齐。P2 暂不做。实际运营材料的结构与导入能力已补全；材料并未给出的学校硬日期、批准权重与预算保留为空或待负责人配置。

v0.8.1 进一步关闭本地 Hermes 的延迟会话持久化/JSON快照，让 Base 统一管理接待记忆。真实本地 Hermes＋联网 DeepSeek 的通用对话、访客/学校/Agent隔离、刷新及服务重启恢复、本人导出、删除后无法恢复已完成专项技术验证，见 `evidence/hermes-sessions/ACCEPTANCE.md`。不提供用户个人 Agent 长期记忆；不把联网模型称为离线模型。其他校园服务的验证仍对应其原版本证据。

v0.8.2增加直接消费完整ZIP及其已校验生产依赖/前端的Ubuntu镜像路线、固定Hermes源码与Python 3.13、仅Base可读取的私有模型密钥挂载及容器重启/全栈验证工具。当前版本的实际执行结果统一记录在 `evidence/ubuntu-hermes/ACCEPTANCE.md`；未形成该验收记录时，打包清单明确保留candidate状态。

人物产品分工以最新约定为准：Base提供简单部件编辑、动作、互动与持久化，学生会提供学校美术。现有原创库保留为可运行占位和旧存档兼容；素材接口与续建提示见 `docs/AVATAR-SCHOOL-ART.md`，未宣称支持任意模型一键导入。
