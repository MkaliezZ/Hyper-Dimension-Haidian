# 四个 Base 的启用与暂停

安装能力由现有 `m2Enabled`、`campusEnabled`、`partnersEnabled` 决定。私有运行配置可用 `modules` 控制已安装模块的新写入，也可在某一 `schools[]` 项中覆盖。例如：

```json
{
  "m2Enabled": true,
  "campusEnabled": true,
  "partnersEnabled": true,
  "modules": { "base1": true, "base2": true, "base3": true, "base4": true },
  "schools": [{ "schoolId": "example", "modules": { "base3": false, "base4": false } }]
}
```

此处是配置片段，实际学校项目、服务 URL 和私有凭据仍按部署指南填写。`base1` 是空间、身份和协议基础，运行中的服务不能将其关闭。类型错误、未知开关、启用尚未安装能力会在启动时明确失败。

修改配置并正常重启对应 Base 进程生效；不迁移、清空或覆盖数据。`GET /m0/me` 的各学校记录返回实际 `modules`，供客户端读取；服务端始终拒绝已关闭模块的新操作，Agent 目录会隐藏对应流程卡。

| 模块   | 暂停后拒绝的新操作                                                   | 继续保留                             |
| ------ | -------------------------------------------------------------------- | ------------------------------------ |
| Base-2 | 人物保存、背包操作、个人页写入、联系人和聊天写入                     | 当前权限下的既有形象、库存和消息读取 |
| Base-3 | 论坛、活动、计分规则、奖励、运营排期、受控附件写入及原生论坛登录授权 | 当前权限下的已存贡献、审核与权益记录 |
| Base-4 | 入驻、服务申请、领取和核销新写入；公开接待不再使用合作来源           | 当前权限下的历史请求和权益记录       |

服务端检查所有新旧业务入口，返回 `module_disabled`；不会只隐藏按钮。身份登录和权限管理继续运行。已接受的跨服务请求对账、到期处理与撤权仍继续，以防暂停掩盖尚未明确的外部结果；这不代表接受新的业务操作。关闭模块不会自动取消已经向真实合作系统提交的订单。

角色与模块是两个条件：模块启用不会给访客管理权限；模块关闭也不会让历史私人记录公开。排名、贡献值和奖励从不自动授予学校或组织管理角色。
