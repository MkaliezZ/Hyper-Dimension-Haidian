# M1 共享底座：本轮优先交付

> **历史范围 / 兼容工具参考。** 本文记录当时里程碑，不是当前完成度或开发优先级。旧的“尚未实现”、功能上限、数据库数量及候选状态不覆盖后续版本；涉及具体命令仍须核对当前脚本和实例。当前流程以[统一开发手册](../DEVELOPMENT-MANUAL.md)及本版验收为准。

> 本文保留 v0.2.0 的账号与组织基础说明。后续 v0.3.0 已补齐私信、范围讨论及原帖修订，当前功能与入口以 [M1-SOCIAL-START](../M1-SOCIAL-START.md) 和 [通信文档](M1-SOCIAL.md) 为准；下文“尚未接通聊天/编辑”描述的是 v0.2.0 的阶段边界。

## 1. 已实现的边界

本轮完成用户指定的四项优先能力。延续 M0 的真实服务集成，没有重新启动旧游戏开发，也没有迁移或覆盖原交付的数据。

| 能力                | 本轮实现                                                                                                                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 正式账号流程        | Keycloak 注册、先验证邮箱再设置密码、密码找回、OIDC 授权码与 PKCE；按 issuer/sub 保留稳定 Base ID。每次 API 检查令牌有效性及当前邮箱；原生桥接检查当前账号是否启用、邮箱是否验证。                                            |
| 学校及组织权限      | 学校负责人、学校审核员、成员；组织负责人、组织审核员、成员、合作方。邮箱绑定的 48 小时一次性邀请；新组织成员默认 affiliate，不自动取得学校成员权限。权限在服务端判断，客户端和模型均不能授予权限。                            |
| 交接与审计          | 权限变更需 expectedRevision，防止覆盖并发修改；最后一位负责人不能被撤销。先增加新负责人，再撤销旧负责人。旧令牌继续调用时读取当前权限。变更与审计在同一事务中。                                                               |
| 事件对账            | 论坛操作先保存意图与原生记录 ID。队列入库、原生发布、原生撤回完成后，若中断，按实际源状态补齐事件；不重新投稿。记录不完整或内容漂移时报告 blocked，保留现场。规范化去重、版本冲突拒绝、贡献冲正、账本重建分数和 outbox 重试。 |
| PostgreSQL 中的 A2A | 任务、上下文、位置、消息、去重回执进入业务 PostgreSQL；保持原协议。原 JSON 只通过显式备份迁移工具导入，原件不变。仍为一个运行进程持有整个状态快照，未宣称横向扩容。                                                           |
| 访客绑定            | 原签名访客 Cookie 证明 + 五分钟一次性凭据 + 已验证账号；不按邮箱/昵称猜测合并。保留原任务 ID 和回执，仅增加所有权别名；与账号现有请求 ID 冲突时拒绝自动绑定。                                                                 |
| 通知                | 审核事件与账号通知同事务写入；eventId 去重、本人读取/已读、游标续取。没有接通私信或实时聊天。                                                                                                                                 |
| 备份恢复            | 停止整套写服务后，备份六个服务数据库、私有配置及密钥、Base 数据目录、学校空间与美术文件、论坛上传、Nakama 模块、Keycloak 配置与主题。SHA-256 清单校验；仅恢复到新目录与新数据库命名空间。                                     |

贡献规则仍是 `m0-content-accepted-v1` 与 `m0-trial`，审核采纳 +10、撤回 -10，**仅为虚拟规则**；用户的旧运营材料到位后另做 M4 配置。本轮未把它说成学校正式激励政策。

## 2. 数据与权限归属

- PostgreSQL：Base 身份、学校/组织成员、邀请、人物、运行状态、事件、账本、通知、回执、审计与恢复对账记录。
- Keycloak：真实凭据、验证邮箱、找回密码、会话；Base 不保存用户密码。`hd-ops` 是只读用户资料服务账号，密钥只保存在服务器私有配置。
- NodeBB：正文、待审队列、原生帖子、操作意图与源事件。M1 使用按学校/组织过滤的桥接入口；原生论坛读写页与 WebSocket 关闭，避免绕过组织隔离。完整原生编辑界面尚未完成。
- Nakama：账号映射与只读贡献投影。原生账户访问也查当前学校资格；普通客户端不能改贡献分。实时聊天仍关闭。
- 向量资料库：保留原 PostgreSQL/pgvector 与 PGlite 实现。论坛、通知、私信、A2A 留言不自动变成公开接待知识；原知识库的发布/撤回与引用检查保持。

学校 owner 可以管理本校组织；组织 owner 只管理本组织，不可授予学校权限。partner 与 affiliate 只能使用明确加入的组织接口。学校/组织撤权立即影响后续请求；已开始执行的外部操作仍需源状态对账，不声称存在分布式事务。

角色迁移使用 `database/m1.sql`、`m1-002.sql`，在事务和数据库迁移锁内执行，保存版本及摘要。已应用 SQL 摘要变化会拒绝启动。失败迁移不重置数据。

## 3. Ubuntu 初始化

前置环境与固定版本同 M0：Node 24 LTS、Java 21、PostgreSQL、git、curl、tar、xz 和 PostgreSQL 客户端，详见 integrations/versions.json。本轮验证环境是同一 Windows 主机上的 WSL Ubuntu，不是新物理服务器或公网部署。

```bash
npm ci --ignore-scripts
npm run setup
bash tools/m0-install-ubuntu.sh /srv/hd-m1-services
export PATH=/srv/hd-m1-services/node/bin:$PATH

# 私有 JSON，字段为 Keycloak 的 SMTP host/port/from/auth/starttls/user/password 等。
# 不提交到 Git，不贴入聊天；正式初始化没有测试 SMTP 默认值。
export HD_M1_SMTP_FILE=/secure/school-smtp.json
export HD_M0_PG_ADMIN='<private PostgreSQL initialization connection>'
node tools/m1-init.mjs --runtime /srv/hd-m1-services --namespace school_m1
unset HD_M0_PG_ADMIN
export HD_M0_CONFIG=/srv/hd-m1-services/private/config.json
node tools/m0-services.mjs setup
node tools/m0-services.mjs start
```

入口默认 `http://127.0.0.1:4380/m1.html`，IdP 为 8280，论坛 4667/4668，Nakama 7550/7650。新学校的稳定 ID/spaceId/空间包路径在私有 config.schools 中设置；不要把两套虚拟 north/south 包误标为真实学校。变更端口/域名应在初始化前设置 `HD_M1_ORIGIN`、`HD_M1_ISSUER`、`HD_M1_FORUM_PORT`、`HD_M1_NAKAMA_PORT`。

这是回环测试启动器。正式公网运行还须完成 TLS/域名/反向代理、非 root 服务账户、真实 SMTP 送达测试、持续运维和容量验证；当前交付不宣称生产上线。Base 当前登录会话到令牌到期后需重新登录；退出按钮清理当前 Base 会话，学校统一 SSO 的全局退出由 Keycloak 管理。

### 第一位学校负责人

学校负责人先通过 `/auth/register` 注册并验证邮箱。服务器维护者核对身份后执行：

```bash
node tools/m1-bootstrap-owner.mjs --school north --subject '<verified Keycloak subject>'
# 或使用能精确匹配单个账号的 --username；只允许建立第一位负责人。
```

已有 owner 时工具拒绝升级其他账号；后续交接走网页，审计留痕。邀请只返回给当前范围的负责人，通过学校自己的受信渠道交给指定邮箱持有人；本工具不会替你发送邀请消息。

### 仅限隔离自动验证

初始化加 `--fixtures` 会创建随机密码的虚拟账号、允许测试密码授权、启用测试故障注入，SMTP 指向 127.0.0.1:2525。只用于全新测试命名空间；正式部署不加此参数。测试 SMTP 接收器为 `tests/m1-mail-sink.mjs`，不向外发邮件。

## 4. 旧状态迁移与访客绑定

迁移前停止对应 Base，保存整个数据目录与数据库备份。向新 M1 业务库显式导入：

```bash
export HD_M0_CONFIG=/srv/hd-m1-services/private/config.json
node tools/m1-import-json.mjs --input /secure/stopped-copy/state.json --backup /secure/new-json-migration-backup
```

目标已有运行状态、仍有运行进程、原件格式不符或备份不一致时拒绝导入。原 state.json 不删除、不改写。迁移的旧访客 Cookie 签名须与该数据目录的 access.json 一起保留。浏览器先 POST `/m1/guest/prepare` 取得短期凭据，再登录并 POST `/m1/guest/bind`；凭据仅可用一次，不允许指定任意目标 userId。若旧访客任务跨学校，账号须已取得这些学校资格。

## 5. 完整备份与恢复

### 创建备份

```bash
node tools/m0-services.mjs stop
node tools/m1-backup.mjs create --backup /secure/backups/new-snapshot
node tools/m1-backup.mjs verify --backup /secure/backups/new-snapshot
node tools/m0-services.mjs start
```

工具拒绝占用端口和仍有客户端连接的数据库，避免把六个独立活跃数据库各自的时间点误称为一致备份。失败会保留不完整目录，但没有 complete 清单；不能拿来恢复。

备份含账号数据库、会话、密钥和私有资料，只能由服务器维护者保管，不能放入公开源码 ZIP。`manifest.json` 包含文件大小和 SHA-256；六库 `pg_dump` 在停止全部写服务期间执行。自定义 pgvector 使用独立服务器时，工具要求该连接存在于 `private/runtime-env.json` 或对应环境变量，否则拒绝声称完成备份；本次实际整套演练为六库配置，额外远程知识库恢复仍需按自己的扩展环境验证。PGlite 数据目录随 Base 数据目录备份。

### 恢复到独立的新实例

```bash
export HD_M0_PG_ADMIN='<private PostgreSQL restore admin connection>'
node tools/m1-backup.mjs restore --backup /secure/backups/new-snapshot \
  --runtime /srv/hd-m1-restored --namespace school_restore \
  --base-port 4480 --idp-port 8380 --forum-port 4767 --nakama-port 7750
unset HD_M0_PG_ADMIN
node tools/m1-bind-restored-services.mjs --runtime /srv/hd-m1-restored --binaries /srv/hd-m1-services
export HD_M0_CONFIG=/srv/hd-m1-restored/private/config.json
node tools/m0-services.mjs start
# 新终端执行，完成克隆实例的 OIDC 跳转地址调整：
node tools/m1-relocate-client.mjs
```

恢复前先校验全部清单。目标目录、角色或数据库已有同名对象则拒绝。恢复不会覆盖源库或停掉源服务。绑定工具复制固定版本服务文件，不共享可写数据目录。新端口会使 issuer 变化，恢复工具在新库中显式调整 issuer，保留 Base userId 和 Keycloak subject；原站点配置不变。克隆实例需重新登录，不能把旧站点令牌当成新 issuer 的令牌。改变了数据库角色/域名之外的生产环境，应先核对扩展安装与 Keycloak 管理方式，不自动修改现网权限。

上线前至少逐表核对六库内容摘要，再验证登录、学校/组织隔离、人物恢复、A2A 任务和重复回执、源事件/贡献账本和 Nakama 映射、公开知识引用。备份完整不等于公网服务已恢复正常。

## 6. 验证与后续边界

```bash
npm run doctor
npm run build
npm test
npm run verify
npm run test:m1
# 独立 QA Chrome + 私有测试 SMTP；不读取用户浏览器。
npm run test:m1:browser
```

自动测试使用真实 Keycloak、NodeBB、Nakama 与 PostgreSQL。保留源服务既有发帖限流，不扩大业务时限；故障注入只对 fixtures 环境和服务凭据开放。

完整 M1 规划仍有后续：私信/聊天逐包权限、完整原生论坛编辑、自动保留/清除策略、生产部署与告警。没有因完成本轮四项优先能力而把这些标为完成。M2 的正式人物素材/背包和 M3–M5 的运营、奖励、合作方业务也未提前展开。
