# 通用运营模板与排期（AC29）

入口：`/operations.html`。学校负责人可管理全校与本校组织；组织负责人只可管理获准组织。每次读取、导入、激活、排期和交接都检查当前权限，贡献排名不授予管理权限。

## 可以做什么

1. 加载包内虚构示例，或上传负责人整理的运营 JSON。
2. 校验模板、来源标签和数据边界，预览相对上版的新增、移除、字段变化及影响。
3. 填写理由并明确确认，导入不可覆盖的新版本；再单独确认激活版本。
4. 选择开始日期、模板、当前负责人、活动核验者与空间位置，可关联已审核规则和已发布奖励。
5. 预览 timeline，确认后在同一事务内创建真实活动草稿，记录每个活动的权威 ID。
6. 打开活动中心继续编辑、提交审核、发布、报名和核验；在运营页查看当前活动状态、参与汇总、实际贡献流水，并导出复盘 JSON。
7. 为已有管理权限的接任者登记负责人交接，保留前任、接任者、理由、时间和版本。

导入不创建活动；激活不发布活动；排期只创建草稿，不批准内容、计分或发奖。缺少生效计分时期会明确提示。实际计分依照事件发生时的有效规则，奖励领取继续经过资格、有效期、库存和审批控制。

## 文件与权威来源

| 文件或模块                                   | 用途                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------ |
| `examples/operations/campus-starter-v1.json` | 原创虚构的迎新、读书会、志愿服务、毕业记忆四个模板；不是用户旧运营材料或学校认可政策 |
| `src/platform/operations.mjs`                | 版本、校验、预览、激活、事务排期、复盘及交接接口                                     |
| `database/m3-operations-001.sql`             | 不可变包版本、激活指针、排期与交接记录；已应用迁移不可编辑                           |
| `public/operations.*`                        | 负责人使用界面，上传 JSON、确认影响、创建草稿和查看复盘                              |
| `src/platform/activities.mjs`                | 活动内容与报名、核验状态的唯一权威；排期调用其 `createDraft`，不复制活动业务状态     |
| `src/platform/campus-ledger.mjs`             | 规则、时期与实际贡献流水；排期不自行建立积分账本                                     |
| `src/platform/rewards.mjs`                   | 奖励定义和实际发放权威；这里只读校验真实奖励引用                                     |

记录只保存版本内容、计划快照、真实活动引用和交接记录。复盘实时查询活动、报名状态汇总和贡献流水，不导出私人证明、联系方式或私信。排期的原始模板版本和创建时引用保留；后续激活新版不会改写已有活动、原排期或历史账目。

## 模板格式

顶层 `schema` 固定为 `hyper-dimension.operations/v1`，其余字段：

- `packageId`：当前学校和管理范围内稳定的包 ID。
- `version`：从 1 开始连续增加；已导入版本不可覆盖。
- `name`、`description`：本套运营安排的名称及说明。
- `sourceLabel`：明确来源，例如“某届学生会批准的秋季活动安排”；不得将示例冒充真实批准材料。
- `exampleOnly`：是否为未经过本校确认的示例，虚构示例固定为 `true`。
- `templates`：1–12 项，每项具有独立稳定 `templateId`。

每项模板只接受以下数据字段：

| 字段                                                   | 约束                                                                   |
| ------------------------------------------------------ | ---------------------------------------------------------------------- |
| `kind`                                                 | `event` 或 `volunteer`                                                 |
| `title`、`description`、`conditions`、`responsibility` | 活动标题、公开说明、条件和责任分工；普通文本，有长度上限               |
| `dayOffset`                                            | 相对排期开始日期第 0–366 天                                            |
| `durationMinutes`                                      | 15–10080 分钟                                                          |
| `registrationMinutesBefore`                            | 开始前 0–10080 分钟停止报名                                            |
| `capacity`                                             | 1–100000 人，仍受实际活动容量控制                                      |
| `remindBeforeMinutes`                                  | 开始前 0–10080 分钟                                                    |
| `tasks`                                                | 最多 30 个含 `id/title/description` 的任务；志愿活动必须至少有一个任务 |

未知字段、重复模板/任务 ID、不合法类型与越界值都会失败。模板不提供脚本、命令、远程插件或可执行表达式字段。上传内容是数据，展示时使用文本节点，不能执行其中的指令。

## 如何接入后续旧运营材料

接手 Agent 先保留原材料与出处，再把活动、相对日期、条件、人数、责任人职责和志愿分工映射到 JSON。无法从材料确定的值列为待确认，不编造学校政策。权重、预算、周期以及奖品资格使用各自模块的审核配置，不能写入模板绕过它们。

负责人先预览差异，再导入新版本并单独激活。对原来已排好的活动需要调整时，在活动中心按其允许的编辑、取消、重新建立流程处理，不能通过改模板暗改参与者已收到的安排。

## 接口与一致性

以下路径前缀是 `/operations/schools/{schoolId}`；组织范围追加 `/organizations/{orgId}`。

| 接口                                                   | 行为                                                                                        |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `GET /contexts`                                        | 学校级入口，列出当前账号可管理范围                                                          |
| `GET /setup`                                           | 当前获准人员、规则和奖励选项，不返回私人联系信息                                            |
| `GET /example`                                         | 读取包内虚构示例                                                                            |
| `GET /packages`、`GET /packages/{id}?version=N`        | 已导入版本、激活指针、版本内容和差异                                                        |
| `POST /preview`                                        | 校验 `{document}`，返回规范化指纹、上版和差异；无业务副作用                                 |
| `POST /import`                                         | `document/expectedLatestVersion/previewHash/confirmed/reason/requestId`；明确确认后追加版本 |
| `POST /activate`                                       | `packageId/version/expectedRevision/confirmed/reason/requestId`；CAS 更新激活指针           |
| `POST /runs/preview`                                   | 校验当前激活版本及真实负责人、核验者、地点、规则和奖励，返回 timeline 与影响                |
| `POST /runs`                                           | 提交相同计划、`previewHash/confirmed/requestId`；事务创建真实活动草稿                       |
| `GET /runs`、`GET /runs/{id}`、`GET /runs/{id}/export` | 排期索引与当前复盘，导出相同受控数据                                                        |
| `POST /runs/{id}/handoff`                              | `expectedRevision/responsibleId/reason/requestId`；仅移交给已有当前管理权限者               |

计划字段为 `packageId/packageVersion/expectedHeadRevision/title/startsAt/responsibleId/verifierIds/sceneId/entityId/ruleVersion/rewardId/templateIds`。人员、地点及奖励可用性都由服务器核验；预览指纹变化必须重新预览。绑定规则必须已审核，绑定奖励必须同范围、已发布且未过期。活动日期已有激活时期时，其规则版本必须与所选规则匹配。

所有写操作保留请求 ID、事务回执与审计。重复提交同一请求返回同一结果；相同请求 ID 改内容失败。版本激活、交接使用 CAS；中途任一活动创建失败，整批草稿、事件、排期和回执一并回滚。回执重放前仍核验当前身份及范围权限。

交接不会自动邀请用户或授予权限。先在正式权限管理完成成员加入和负责人授权，再在这里登记运营责任交接。原活动创建者和审核记录不被改写；接任负责人依现有管理权限继续处理。失去权限的前负责人不能使用旧回执继续管理。

## 验证与边界

- `node --test tests/operations.test.mjs`：严格格式、字段拒绝、差异与旧版本保护。
- 在独立校园测试实例、`HD_M1_TEST_FIXTURE=1` 下执行 `node tests/operations-live.mjs`：5 组接口链路，包括跨学校/组织拒绝、真实规则/奖励引用、预览冲突、事务中途失败回滚、幂等并发、实际活动发布与报名反馈、负责人交接。
- 提供 `HD_QA_CHROME` 的独立浏览器环境执行 `node tests/operations-browser.mjs`：导入、确认激活、四个真实草稿、复盘下载、活动入口、窄屏与无权限账号。
- 当前证据在 `qa/operations/`。所有学校、账号、内容和运行安排均为隔离测试数据；这些证据不代表实际学校运营、目标服务器部署或真人验收。

活动流程见 `docs/ACTIVITIES.md`，计分和时期见 `docs/CAMPUS-LEDGER.md`，奖励见 `docs/REWARDS.md`。部署备份必须纳入这三张运营表及其关联的活动、账户、原生服务和贡献数据；单独导出复盘不构成完整备份。整套实例停写、备份与新命名空间恢复验收由交付流程统一执行。
