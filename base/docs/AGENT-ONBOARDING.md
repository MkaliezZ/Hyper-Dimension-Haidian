# 一句话引导参考

主流程已统一到 [DEVELOPMENT-MANUAL.md](../DEVELOPMENT-MANUAL.md)；本文件补充首次回复分支。完整校园优先按手册与容器部署执行，下文 PGlite / npm start 默认仅指轻量空间示例，不代表完整校园模式。

## 目标与触发

面向不了解代码、模型、数据库的学生会使用者。用户上传完整 ZIP 并问“这是做什么用的？怎么用？”、“这个包怎么开始？”等问法即可进入引导。用户无需先打开 README、填写模板或复制 prompts。接手 Agent 需要具备解压、读取文件的能力；开发和实际运行还需要相应代码执行环境。

本文件是接手 Agent 的操作约定，不是已经运行在所有第三方 Agent 中的自动化服务。以实际读包、运行和校验结果为准。

## 0. Agent 自己完成发现

1. 检查附件能否解压到独立可写目录；保留已有文件和修改，不覆盖同名学校项目。
2. 读取根目录 AGENTS.md、AGENT-START.md、START-HERE.md、PACKAGE-STRUCTURE.md。
3. 确认可用能力：Node 场景、学校项目、A2A、资料向量库与接待；环境/模型/资料缺项在对应阶段检查。
4. 用不超过三个短段解释“能帮用户做什么、用户提供什么、你负责什么”，随后只问一个当前选择。不要把端口、venv、Embedding 维度、SQL、终端命令作为第一次回复的主体。

首次回复示例在 AGENT-START.md。用户已提供学校名称、图纸或明确请求时直接复用，不从头重播介绍。

## 1. 先看示例

用户选择先看示例或要求帮忙启动后：

- 读 STARTUP.md，检查包完整性、Node 与可写目录。先核对已有服务和端口，已有正确示例可复用；需要新实例时用独立数据目录和空闲端口。
- 启动包内原创 north/south 场景，实际确认地址可访问，再告诉用户去哪里点“开始参观”、选择房间和换层。
- 说明当前接待是资料模式还是已实际连通的模型。示例资料是虚拟内容，不能直接冒充用户学校。
- 接下来问：“准备搭建哪所学校或哪栋楼？可以先给平面图或草图。”只收集当前需要的信息。

用户机器尚无 Node 时说明缺少哪个环境，并提供具体安装步骤；执行软件安装依用户环境和授权处理。不能把文档里有启动命令说成服务已启动。

## 2. 直接搭建学校

用户选择搭建、给出目标或上传学校材料后，自行读取 prompts/00-BUILD-SCHOOL.md 和 AGENT-WORKFLOW.md，不让用户再复制它们。

| 已有输入         | 下一步                                                     |
| ---------------- | ---------------------------------------------------------- |
| 学校名＋平面图   | 读图、记录尺度/楼层/推定、建立独立学校项目，生成可运行场景 |
| 只有平面图       | 先按建筑处理，不编造学校归属；可用中性项目名，学校名后补   |
| 只有学校目标     | 询问是否有平面图、尺寸草图或照片；可先做明确标注的概念布局 |
| 没有正式美术     | 使用原创/获准占位素材，保留可替换接口并记录来源            |
| 没有学校文字资料 | 先做场景和基本房间信息，真实学校事实保持未提供             |
| 已有学校项目     | 读项目交接、输入索引与 Git 差异，继续未完成项，不覆盖重建  |

由 Agent 根据对话填写 templates/school-input.example.json 的项目副本并维护 HANDOFF.md；不要求用户手工填写技术 ID、路径或 schema。涉及校方事实、绝对尺寸和素材权利等业务判断时，向用户询问具体缺项。

### 原型之后：主动带用户做美化

基础模型能走通后，明确告诉用户“这版先验证结构，下一步可以升级美术”，不要把简陋体块直接作为可展示的最终成果。自行读取 prompts/04-VISUAL-POLISH.md，提供校园清爽、温暖手绘、轻科幻等可理解的选项；有参考图就沿用，用户让你决定时默认校园清爽。

Agent 先用一个入口和一个房间建立视觉基准，补充协调的 2.5D/3D 素材、材质、植物、家具、导览牌、展板与灯光，再延展整体并核对可通行与可读性。让用户看到前后差异；用户只需提供学校照片、喜欢的参考或确认方向，不用自己列技术美术任务。缺校方素材时用明确标注的原创占位，记录后补事项。

若用户目标是完整可展示空间，美化阶段是交付的一部分；若用户仅要原型或主动暂缓，则记录当前阶段和下一步。交接采用“结构原型 / 视觉升级 / 待校方素材 / 可展示候选”的明确状态，防止用户不知道下一步做什么。

## 3. 让接待使用学校资料

当用户提供公开手册、社团介绍、场地规则等：

1. 读 KNOWLEDGE.md，核对内容来源和允许公开范围，整理 documents.json。原件和未公开资料保留在私有目录，先过滤再向量化。
2. 默认按包内已提供的本地 PGlite＋pgvector 和中文 ONNX 模型走通；用户已有 PostgreSQL 时复用适当的专用数据库配置。不要未经用户选择连接或改写任意现有数据库。
3. 用实际问题与改写问法核对命中、引用、跨校隔离、撤回与重启。校方内容正确性由真实资料确认，不由模型补齐猜测。
4. 用户要通用交流时，按 LOCAL-AGENT.md 配 Hermes；敏感值走本机环境，避免让用户在聊天里给出完整密钥。缺密钥时先完成不依赖它的工作，并标记模型联通尚未验证。

普通用户只需提供资料、确认业务信息；Agent 负责模型维度、数据库建表、命令、配置和错误定位。需要更换默认方案时解释实际影响，不把全部技术选型丢回用户。

## 4. 持续推进与交接

- 在 projects/<school>/HANDOFF.md 保存：目标、已给材料、已完成项、下一步、需用户补充项、已验证和未验证边界。续聊先读记录。
- 每次只问阻碍当前下一步的关键问题，通常一题；其余独立工作继续推进。用户已给的信息不能重复索取。
- 完成的阶段展示真实产物和地址，例如“这个入口已可走入，下一步补场地资料”；不要只给设计文字或把生成网格当运行验收。
- 交付项目、部署说明、可复建命令、来源、推定清单和实际验证证据。公共 Base、私有学校包、个人配置分别管理。
- 对原始图纸精度、实际学校内容、真人体验、独立服务器和物理跨设备测试，按已发生的证据说明，不自动写成已通过。

## 维护者检查入口是否齐全

打包时核对：根 AGENTS/AGENT-START/START-HERE/README 都能发现本流程；prompts 是 Agent 内部清单而非用户必贴内容；链接能在解压包内打开；原有运行库、模型、示例、协议和配置模板均保留。文档与完整性检查不代表已对所有第三方 Agent 做过真人引导验收。
