# 学年运营、渠道工作与自愿行动清单

入口 `/annual.html`。这部分把年度参考资料转成可筛选、可交接的工作，不把整份年历自动分配给每名学生。

## 四个 Base 如何衔接

| 模块 | 本轮补全与既有功能的衔接 |
| --- | --- |
| Base-1 | 把校历、公开指南与资料复核列入公域运营事项，保留来源、核对日期、适用范围及准备窗口。实际公开资料仍经既有接待资料发布与自动向量索引，不自动抓取、执行 HTML 或把运营底稿灌入接待 |
| Base-2 | 成员按适用年级和本人需要自愿选择行动，服务端存档、CAS 修改、完成/不适用解除评级、自行删除。同学年同主线去重。学校负责人没有读取他人行动清单的接口；不建立家庭联系人或自动通知家人 |
| Base-3 | 学年起始月份、跨年月份、年级、客观/学业/职业/生活/校园活动分类、活动/公域/私域渠道、版本审核与启用、负责人分工、实际日期核对、草稿联动与交接记录。审核、论坛、活动核验、贡献排名和奖励继续使用原权威模块 |
| Base-4 | 合作方服务复核可以进入年度工作并打开合作服务入口。办理、同意转交字段、限定委托 A2A、外部回执与对账沿用已有模块，不因为年历里写了“办卡/团购”就产生交易或自动分享个人信息 |

ABC 是个人当前情境的参考等级，不是贡献值。客观事件不评级；完成或不适用时解除评级。最佳投入窗口、持续过程、直接影响与条件性后续影响单独保存。参考月份不是硬截止，实际日期必须另行核对。不新增收费交易、抢票、金融办理、招聘 ATS、重型捏脸或个人模型长期记忆。

## 导入材料

本包只附原创示例 `examples/operations/annual-starter-v1.json`。使用者自己的材料保留在私有项目，不进通用源码包。当前转换工具支持本轮的“月×年级、活动/公域/私域”工作表和内嵌 JSON 年历；不声称支持任意 Excel/网页格式。

```sh
python3 tools/prepare-annual-materials.py --xlsx /private/activities.xlsx --html /private/calendar.html --out /private/NEW_CONVERSION
node tools/annual-validate.mjs /private/NEW_CONVERSION/student-union-annual.json
node tools/annual-validate.mjs /private/NEW_CONVERSION/student-needs-annual.json
python3 tools/verify-annual-materials.py --xlsx /private/activities.xlsx --html /private/calendar.html --converted /private/NEW_CONVERSION
```

转换工具仅用 Python 标准库读文件。HTML 用 JSON.parse 对应的纯数据解析，不运行脚本。遇到公式要求先提供审核后的纯值副本，不执行公式。输出目录已存在则拒绝覆盖；原文件不改。空白指标、未给出的日期、计分权重、费用、预算不补造。每个输出保留原文件 SHA-256 与单元格或来源引用。

负责人上传 JSON，预览新版本差异，明确确认导入，再另行启用。普通成员只能读当前启用版本。草稿资料、其他学校、无权组织不通过本入口读取。公开指南、私域答疑、活动计划的“渠道”只是工作方式，真实权限仍由学校和组织 ACL 决定。

核对工具独立逐项比较来源与转换稿，检查学生需求、评级条件、适用分支、时间窗口和引用等，输出 `source-fidelity.json`。通过来源对照仍需负责人审核实际适用性。首次转换默认资料版本 1；若同一范围已导入旧稿，先读取最新版本，再使用 `--version 最新版本加一` 输出到新目录；不能覆盖或重写已导入版本。旧计划采用新版也需明确复核。

界面每页最多 24 项，跨页及跨筛选保留选择并显示总数；更换学校、组织、资料或学年会清空。学生需求单独展示，背景口径和适用分支可展开。清空选择或更换上下文后须重新预览分工；公域指南工作可打开接待资料管理，但不自动发布。

## 工作与行动

1. 选择学校、范围、启用资料及学年开始年份；根据学校设置的起始月份映射到次年月份，只产生 `YYYY-MM` 规划标签。
2. 按年级、月份、分类或渠道筛选，不要求学生接受整张表。
3. 负责人选取至多 100 项，指定当前有管理权限的负责人，预览后确认建立运营事项。已有同学年同来源条目拒绝重复建单。
4. 核对实际日期，保存理由、负责人和日期依据。交接不自动授予权限，接任者必须已有相应管理权限。
5. 只有活动渠道可另行创建活动草稿。要求实际日期已确认，来源版本仍是当前启用版。草稿仍需活动中心审核、发布、报名和核验，不能从建单获得积分。
6. 更换资料版本不改写旧工作。需要采用新版时，在事项上明确勾选复核当前来源；原快照、版本与交接理由保留。已建活动不会由新资料静默重写。
7. 个人行动清单只由本人操作，同学年同主线只有一条当前记录；后续月份可明确替换这一记录。个人状态、等级与截止不进入论坛索引、公开接待或模型提示，也不计分。

## 数据格式与接口

格式为 `hyper-dimension.annual-operations/v1`。顶层含 `packageId/version/name/sourceLabel/sourceHash/exampleOnly/startMonth/cohorts/references/assumptions/entries`。每项保留稳定 `entryId/chainId`、月份、年级、类别、渠道、标题、描述、学生/可选家庭需求、适用条件、各时间窗口、参考等级、来源引用和对应 Base。

来源网址仅接受 HTTPS 或空值，不包含账号密码。日期核对可保留原材料的日期精度，不凭空添加时刻。空白不替换为零，也不表示该年级已无需求。每包最多 1500 个参考情境；超过请求大小时拆分来源包。

接口前缀 `/annual/schools/{school}`，组织范围追加 `/organizations/{org}`：

| 接口 | 权限与作用 |
| --- | --- |
| GET contexts/packages/catalog/example | 当前学校成员；组织按现有资格过滤；成员仅看启用版本 |
| GET versions/{package}?version=N | 当前范围负责人读取原版本 |
| POST preview/import/activate | 负责人审核、不可覆盖版本、CAS 启用；均不发布、不发奖 |
| GET tasks、POST tasks/preview、POST tasks | 负责人读取、预览与创建本范围分工；原请求重试得到同一回执 |
| POST tasks/{id} | CAS 修改负责人、状态、核对日期及理由；可明确复核新版来源 |
| POST tasks/{id}/activity | 确认后调用已有 createDraft，同一事务记录活动引用 |
| GET mine、POST mine、POST mine/remove | 当前用户自己的行动；不接受 userId 代查，不对管理员开放他人正文 |

私有选择不写入审计正文或公共事件；回执只记录操作结果和修订号。权限撤销后读写及旧回执重放均重新验证。Base-3 关闭时此模块拒绝读写。四张新增表纳入 Base 数据库完整备份，不能用复盘导出替代全栈备份。

验收：原契约、隔离接口与备份恢复记录在 `evidence/annual`。v0.7.1 的来源核对、转换回归与两份完整实际材料的前后端流程在 `evidence/annual-materials`；复做入口为 `tests/annual-materials-live-browser.mjs`，须明确开启专用测试开关、使用虚构组织和回环地址。实际材料测试也不代表真实学校批准、学生试用或运营效果验证。用完关闭专属测试服务与浏览器。
