# 接待身份、维护职责与流程助手

本模块把空间接待、活动安排和合作服务的入口汇集在 `/agents.html`。访客先看到谁负责资料、回答依据是什么，以及下一步会打开哪个实际办事页面。空间右侧接待面板同步显示当前空间真实的 Agent 名称、Agent ID 和维护职责。

## 三类入口

| 类型             | 当前能力                                                                                | 权威来源                                                                | 维护职责                                           |
| ---------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| 空间接待 Agent   | 实际 A2A 1.0 接待、已发布资料查询、导航及用户主动留言；配置模型后提供标明性质的通用交流 | 当前加载的空间包与真实 Agent Card；知识查询沿用接待服务的发布与来源校验 | 当前学校负责人角色                                 |
| 活动流程助手     | 展示获准活动；进入实际活动页面，由用户阅读资格、时间与分工后确认报名                    | 本校当前已发布、未结束的活动记录与修订号                                | 该组织负责人；全校活动由学校负责人负责             |
| 合作业务 Agent | 真实 A2A 查询获准服务、受委托创建待确认工单、查询及取消自己受托的工单；敏感资料转交仍由用户在业务页面确认 | 已批准且未到期的合作方、已发布服务、当前委托范围和业务回执 | 当前有效的合作方服务维护者；必要时由学校负责人处理 |

接待与合作业务 Agent 链接各自真实 A2A Card。活动仍为“流程助手 · 用户操作”。合作业务 Agent 需要正式账号创建限定学校、服务、技能和期限的委托，不能代替用户确认个人资料外传，也不能发奖或调整权限。未配置外部服务适配器时，合作流程显示不可用或待处理，不能将本地请求记录表述为商家已完成履约。配置与调用见 [合作业务 A2A](PARTNER-A2A.md)。

维护职责按实时学校、组织与合作工作人员权限派生，不公开真人姓名、邮箱、联系方式或内部用户 ID。卡片的 `assigned` 表示当前确有有效账号持有该职责；没有负责人时显示待指定，并显示是否存在学校负责人升级处理路径。负责人可在现有学校、组织或合作服务管理页面分配职责，目录本身不授予角色。

## 使用流程

1. 正式账号登录后打开 `/agents.html`，选择自己有权访问的学校，按名称或类型查找入口。
2. 阅读能力、维护职责和来源。空间接待卡可以查看真实 A2A Card；流程助手提供实际业务页面入口。
3. 点击入口时先重新查询当前卡片，再进入目标页面。已撤回、取消、到期或失去权限的来源会拒绝打开。
4. 报名、留言、预约、信息转交或权益领取仍在各自页面执行现有的显式确认流程。仅打开目录或合作详情不会创建预约任务。

空间页面会根据当前 `spaceId` 找到已登录账号可访问的学校并读取同一目录。未登录或无法验证职责时，界面保留包内 Agent 身份，并明确提示维护职责尚待登录核对，不编造负责人。

## 读取 API

接口沿用 `/m0/me` 对应的正式 OIDC 会话 Cookie。

| 方法与路径                                                    | 用途                                              |
| ------------------------------------------------------------- | ------------------------------------------------- |
| `GET /agent-directory/schools/:schoolId`                      | 返回当前学校可见卡片及查询时间、模块开关          |
| `GET /agent-directory/schools/:schoolId/cards/:encodedCardId` | 重新校验并读取单张当前卡片；卡片 ID 必须 URL 编码 |

该前缀仅支持 GET。未登录为 401，跨校或缺少学校访问权限为 403，隐藏、撤回或不可用卡片为 404；写入请求为 405。

卡片结构版本为 `hyper-dimension.agent-directory/v1`。主要字段包括 `id`、`kind`、`schoolId`、`spaceId`、`orgId`、`name`、`description`、`maintainer`、`protocol`、`capabilities`、`sources`、`answerBasis` 和 `actions`。接待与活动卡片的下列能力均为 false：

```json
{
  "privateInformationAccess": false,
  "authorityEscalation": false,
  "rewardIssuance": false,
  "delegatedExecution": false
}
```

合作业务卡片的 `delegatedExecution` 与 `privateInformationAccess` 为 true，后者仅限调用者自己获委托的业务工单；`authorityEscalation` 与 `rewardIssuance` 仍为 false。这些字段说明能力边界，不是客户端授权。A2A 网关独立检查实际注册的 skill、委托、学校、当前权限和业务来源，重放缓存结果也重新检查。模型输出不能新增未注册能力。

## 集成与实时失效

```js
createAgentDirectory(db, identity, services, config, {
  getWorld: () => world,
  getPartnerSources: partners.publishedSources,
}); // -> { handle, directory }
```

`directory(schoolId,userId)` 在数据库事务内取得学校权限与信息发布的共享锁，然后重查当前 ACL。活动按组织范围过滤；合作服务复用 `publishedSources(schoolId,client)`，同事务读取当前来源、有效期、地点状态和维护职责。Base-3 或 Base-4 被关闭时，其对应流程卡片不会出现。该目录不新增数据库表，也不产生另一套人员或权限存储。

目录卡片是查询时的投影。取消活动、撤回服务、合作方到期、撤销成员或工作人员资格后的下一次请求即重新判断；前端动作按钮也会在跳转前复查。已打开业务页面后，所有写入仍由相应业务 API 再次验证当前权限与来源。不能以保存的旧卡片绕过撤权。

## 信息边界

- 目录查询不读取私信正文、联系人、私人收藏、内部附件、知识库原始私有输入或模型密钥。
- 目录中的维护字段是职责，不包含人员档案；组织与合作名称来自当前可见业务记录。
- 接待继续沿用既有已发布知识和审核合作资料的来源管线。打开目录不会把内部业务记录自动写入向量库或模型提示。
- 活动与合作页面显示的请求状态、核验结果及履约回执以各自权威业务记录为准。
- 接待可以解释、导航和接收主动留言。涉及外部转交的字段授权仍由用户明确选择，页面跳转本身不是授权。

## 自动验收与证据

在隔离测试配置下设置 `HD_M1_TEST_FIXTURE=1`，运行：

```sh
node tests/agents-live.mjs
node tests/agents-browser.mjs
```

浏览器脚本需要 `HD_QA_CHROME` 指向专属 Chrome，`HD_M0_CONFIG` 和 `HD_M0_USERS` 指向被排除在交付包外的私有配置。live 脚本仅创建虚构测试活动、合作方和服务；浏览器使用独立上下文，不读取用户浏览器。

v0.5 留存的隔离 campus 验收结果（合作业务 A2A 的新证据另见 `evidence/integrations`）：

- `qa/agents/live.json`：3/3 通过。覆盖登录与跨校拒绝、只读限制、实际 A2A Card 与未注册发奖 skill 拒绝、草稿隐藏、组织隔离、活动取消和服务撤回后立即失效。
- `qa/agents/browser.json`：3/3 通过。覆盖真实目录身份与维护职责、活动详情跳转、合作服务显式确认入口且无自动创建任务、空间接待身份、390 px 窄屏布局与无页面脚本错误。
- `qa/agents/directory.png`、`reception.png`、`mobile.png`：对应页面截图，已查看排版与可读性。

上述为本机隔离服务、虚构账号和专属浏览器的自动验证。它证明这些 API 与浏览器链路已连通，不代表真实学生参与、外部合作方履约、物理多设备验收或目标生产服务器验收。独立学校上线仍需配置实际负责人、审核公开资料及正式合作渠道。
