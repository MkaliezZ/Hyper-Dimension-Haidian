# Base-3 社区、组织主页与地图记忆

## 功能与内容归属

`/community.html` 提供学校/组织主页、原生论坛分类、正文搜索、分页、草稿、评论、地点关联、审核、举报、作者撤回和申诉。使用既有正式账号和学校/组织角色，无需第二套论坛密码。

| 数据                                                    | 权威来源                                  |
| ------------------------------------------------------- | ----------------------------------------- |
| 学校、组织、成员、负责人角色                            | Base 现有身份与权限表                     |
| 主页介绍、主页地点、版本                                | Base 的 `hd_community_pages`              |
| 正文、待审内容、原生 pid/tid、编辑版本                  | 独立 NodeBB 服务的原生 queue/posts/topics |
| 稳定 sourceId、分类/地点关联、举报/申诉理由、工作流回执 | NodeBB 插件的版本元数据                   |
| 附件字节、文件类型、所有者、保留期限                    | Base 受控附件模块                         |
| 已获准贡献、冲正、投影                                  | 既有 NodeBB 事件对账和贡献账本            |

Base 不再建立一份论坛正文库，也不新增计分账本。人物私密资料、私信、接待对话和用户原始图纸不会自动成为论坛内容。论坛内容不自动进入接待 Agent 的公开知识库。

## 学生与组织使用流程

1. 登录并选择学校。组织列表只包含当前有权进入的组织，负责人可管理相应范围。
2. 查看社区主页、负责人和组织活动入口。负责人可修改主页介绍和公开地点；更新使用版本检查，防止相互覆盖。
3. 在分类板块撰写故事或进入已发布主题写评论。选择学校内的公开地点后，它同时成为地点记忆。
4. 保存私有草稿，按需上传并绑定附件，再提交审核。草稿未保存的修改不能直接提交。原生论坛冷却期仍然有效，界面保留草稿并提示稍后提交。
5. 当前范围版主填写理由，批准或退回投稿。普通成员只看到已发布内容；作者与版主可以查看待审内容。
6. 已发布正文可提交编辑稿，审核通过前原正文继续有效。批准编辑保留原 pid/tid，产生新源版本，不重复获得首次发布分数。
7. 成员可举报，版主可关闭举报或隐藏内容。作者可撤回自己的内容；被隐藏/退回的作者可提交申诉，由版主填写复核理由并恢复或驳回。

权限管理仍在既有 `/m1.html`，最后一位负责人保护和角色变更审计继续适用。论坛版主权限不包含私信阅读。主页显示职责所需的负责人名称和账号 ID，不返回邮箱、认证主体或私人联系方式。

## 状态、地图与版本

- 草稿仅作者可读；提交后进入原生待审队列。
- 退回的待审稿保留原生队列正文，供作者申诉；没有发布事件，也不会计分。
- 发布生成既有 `published` 源事件。隐藏或作者撤回生成既有 `withdrawn` 事件，冲正同一内容的有效贡献。
- 校园版本使用 `docs/CAMPUS-LEDGER.md` 的已批准规则及已激活时期；没有配置时不自动套用示例分值。编辑可保留一条增量为零的解释流水，表明新源版本已处理但不重复计分。测试先在独立组织明确批准并激活虚构规则，再验证发布、编辑、隐藏、恢复和撤回的实际计分与冲正。
- 隐藏与申诉是原生源元数据中的工作流状态，不另造贡献事件类型。申诉恢复已发布内容时产生新的 `published` 版本；恢复退回的待审稿时，首次提交原生队列发布。
- `revision` 表示内容源事件版本；`workflowVersion` 表示举报/审核等工作流版本。改变工作流必须同时提交当前两个版本、请求 ID 和理由，竞争操作只有一个成功。
- 重复请求内容完全相同则返回既有回执；同一请求 ID 换内容会冲突。原生写入意图、事件与恢复逻辑保留，发布后断连可对账恢复。
- 地点以 `sceneId + entityId` 关联。几何更新保留稳定 ID 时关联不变；已移除或私密地点不再被新的地点查询接受。地图查询直接查看同一 NodeBB 内容状态，隐藏或撤回后立即从其他成员的地图/搜索/详情消失。
- 一个主题的评论继承主题的分类和地点。主题不可用时，普通成员不能通过评论列表或详情绕过访问控制。

可从场景链接进入地点列表：

```text
/community.html?school=north&sceneId=<sceneId>&entityId=<entityId>
```

组织入口可再加 `organization=<orgId>`。参数不会授予权限；服务端仍按当前学校与组织成员资格判断。

## 分类、搜索与附件

分类由获准版主通过 NodeBB 原生 category API 创建，分类也绑定组织范围。搜索在完成当前权限、发布状态、组织和分类过滤后读取原生正文，支持中文、标题及正文的字面包含搜索；每页 1–50 条。它是直接查询源内容的首版实现，不是向量检索或大规模搜索集群；大规模部署需测量真实数据量，再引入独立索引且继续回查权威状态。

草稿创建时预分配稳定 sourceId，提交使用同一 ID。附件上传指定 `purpose: community`、`targetId: sourceId`，组织内容同时指定 `scopeId`。绑定时核对附件所有者、用途、目标和可用状态，只允许作者在提交前绑定，最多八个附件。附件不是公开静态文件：下载同时检查附件权限和论坛当前源状态。公开浏览器链接不含密钥，也不把附件内容内联执行。允许类型、单文件限制、过期、删除及保留策略以 `docs/ATTACHMENTS.md` 和附件模块为准。

## 接口与扩展点

根路径为 `/community/schools/{schoolId}`，组织范围在其后增加 `/organizations/{orgId}`。

| 接口                                                        | 用途                                                                                            |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `GET /contexts`（学校根）                                   | 可进入的组织和学校范围                                                                          |
| `GET /home`、`POST /home`                                   | 主页、负责人、可选地点；负责人版本更新                                                          |
| `GET /categories`、`POST /categories`                       | 原生分类列表与创建                                                                              |
| `GET /posts?page=0&limit=20&query=词&category=id&parent=id` | 主题/评论分页和正文搜索                                                                         |
| `GET /map?sceneId=id&entityId=id`                           | 当前地点的已发布主题                                                                            |
| `GET /drafts`、`POST /drafts`                               | 作者草稿列表、保存与版本校验                                                                    |
| `POST /submit`                                              | 提交指定草稿版本                                                                                |
| `GET /post/{sourceId}`                                      | 原生正文、源 ID/版本、当前允许查看的工作流                                                      |
| `POST /post/{sourceId}/attachments`                         | 作者为草稿绑定受控附件 ID                                                                       |
| `POST /edit`                                                | 沿用原生编辑审核流程                                                                            |
| `POST /action`                                              | approve/reject/report/hide/withdraw/appeal/review-report/review-appeal/approve-edit/reject-edit |

`createCommunity(db, identity, services, config, {getWorld, validateAttachment})` 返回异步 handle，并提供 `handle.canReadAttachment(c, {schoolId,userId,attachmentId,sourceId})` 给附件模块。`validateAttachment` 是附件模块的所有权/用途/目标检查钩子，不由前端结果代替。

本地 SQL 迁移为 `database/m3-community-001.sql`，只新增主页元数据表。原生扩展位于 `integrations/nodebb/community.cjs`，由同目录 `index.cjs` 注册，与已有桥接路由共用串行队列。发布时需复制整个插件目录并按 NodeBB 的 GPL 许可要求保留源码与许可证。原生 HTTP 和 Socket 写入口继续关闭，不能绕开 Base 范围检查或审核事件。

## 验收与边界

```sh
node --test tests/community.test.mjs
# 隔离服务和虚构账号配置下：
HD_M1_TEST_FIXTURE=1 node tests/community-live.mjs
# 设置 HD_M0_CONFIG、HD_M0_USERS、HD_QA_CHROME 后：
HD_M1_TEST_FIXTURE=1 node tests/community-browser.mjs
```

`qa/community/live.json` 记录真实隔离 NodeBB/数据库链路：学校/组织拒绝、主页竞争、草稿/附件权限、原生故障恢复、分类/正文查询、地图源一致、编辑版本、举报隐藏、申诉恢复、作者撤回与同账本冲正。`browser.json` 和截图记录独立自动化浏览器的撰写、审核、下载和撤回流程。

原生服务限流属于被保留的行为。验收按服务返回的冷却时间等待，不降低限流，也不提高发布/贡献断言来通过测试。测试使用同机隔离服务和虚构账号；真实学校运营、生产容量、物理多设备和目标 Ubuntu 服务器部署需单独验收。完整多数据库备份恢复以交付总验收记录为准，不能仅依据论坛接口成功认定恢复完成。
