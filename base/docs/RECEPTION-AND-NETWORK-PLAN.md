# 接待会话与校园连接扩展计划

> **历史范围 / 兼容工具参考。** 本文记录当时里程碑，不是当前完成度或开发优先级。旧的“尚未实现”、功能上限、数据库数量及候选状态不覆盖后续版本；涉及具体命令仍须核对当前脚本和实例。当前流程以[统一开发手册](../DEVELOPMENT-MANUAL.md)及本版验收为准。

日期：2026-10-24。基线：校园 v0.7.1 / e08b95c；本轮新候选不得覆盖封存交付。

## 范围调整

个人 Agent 长期记忆从 Base 路线中移除。用户自带的本机 Agent 自行管理其记忆；Base 仅保存和管理服务器接待产生的会话。校友发现、学长/导师支持、职业机会三个 P1 现已获准开发。地区/跨校社群、复杂交易仍按原 P2 暂缓。

## 1. 服务器接待会话

- 一个用户访问一个学校/空间的接待时，服务器创建随机逻辑 session/context。键包含真实 owner、space/school、agent，不能相信浏览器提供的 userId。用户可以新开独立会话，也可继续自己未过期的会话。
- 沿用 PostgreSQL 权威存储及 A2A owner/context 隔离；独立 Base-1 示例兼容原文件存储。每个会话是数据记录，没有每用户常驻的 Hermes/模型进程。模型调用设置有界并发/排队，同一会话写入按顺序处理。
- 用户确认默认保留 **30 天**，学校负责人可在后台配置。用户可列出、继续、导出自己的 JSON 会话、清空/删除。导出包含本人原问题、回答、时间和来源标记，标为历史对话，不提供密钥、系统提示或模型内部思考。
- 持久保存会话历史；模型只接收有界近期上下文。学校事实每轮重新检索有效发布源。历史交流和未来摘要都不是新的事实权威，不进入公开知识向量库。
- 删除/到期须清除会话正文和可重放的缓存正文；请求身份保留必要墓碑，旧 messageId 不能复活被删除对话。在途调用完成前再次检查会话状态，不能在用户删除后重新落回正文。
- 后台配置期限、查看会话数量/状态/模型失败等最小诊断、清理过期会话。学校管理员默认没有无限查看所有会话正文的权限；需要转交具体问题时采用用户明确授权的流程。

## 2. 校友/成员发现

- 使用者自愿建立独立的发现名片，选择公开给本校成员的姓名/昵称、院系、届别、兴趣、经历和愿提供的支持。默认不进入目录，不自动复制私人资料。
- 草稿→提交→负责人/管理员审核→本校目录。修改需重新审核；退出、暂停或学校资格撤销后，页面、搜索、地图与旧链接立即按当前状态判断。
- 搜索支持关键词、院系、届别、兴趣与身份类别，分页返回。联系使用已有联系人同意与 Nakama 私信，联系方式不作为公开字段。
- 负责人/管理员管理审核、下架、分类和必要标记，带原因、版本和审计；“校友/导师自述”与学校实际核验必须分别标注。

## 3. 学长/导师支持

- 基于已审核且本人自愿提供支持的名片，建立领域标签、支持说明和时段；支持人可管理自己的时段，管理者可协调/取消并留下理由。
- 学生申请→支持人确认/拒绝→取消或完成。防止自约、容量超卖、重复预约和同一支持人时段重叠；问题仅对参与者和获准协调人员可见。
- 接入既有站内通知和联系人授权；不自动创建外部会议、外发个人资料、收款或声称匹配成功。学校可把支持点设置在学院楼、咨询室或地图地点。

## 4. 职业与机会

- 支持实习、岗位、奖助/项目机会、经验交流和咨询活动分类，保留来源、组织、截止、适用对象、地图地点和可选官方申请网址。
- 复用 NodeBB 原生正文、编辑与审核。Base 只保存机会结构化元数据和原生内容引用，避免再建一套帖子正文与审核权威。
- 投稿/编辑→原生审核→机会卡片/地点入口；撤回、隐藏、到期、组织权限变化即时失效。支持收藏/关注及官方申请入口，不代投简历或自动转交个人资料。
- 后台具备本校/组织范围的审核、下架、截止维护与统计。企业合作身份沿用 Base-4，不赋予任意校园公告发布权。

## 5. 页面、建筑与地图统一入口

- 普通 UI：成员目录、支持预约、机会列表和各自管理页，提供筛选、详情及明确操作。
- 空间 UI：负责人将获准条目绑定现有公开 sceneId/entityId；用户点击建筑/房间/地图点位后，看到对应功能卡片并进入相同的详情/确认页。
- 页面、地图与三维场景使用相同稳定对象 ID 和服务端权限。点位不授予管理权限、不自动报名，也不能绑定其他学校或私有/已删除房间。
- 撤回、到期或权限变化后，即使旧卡片仍在客户端也必须在操作前拒绝；模型不得从地图私自读取个人名片或预约。

## 6. 开源技术决定

| 能力 | 主线 | 本项目负责 |
| --- | --- | --- |
| 账号、学校资格 | 已集成 Keycloak | 自愿加入、学校角色和审核规则 |
| 目录/预约/会话事务 | 已集成 PostgreSQL、现有回执/锁 | 领域字段、当前ACL、预约状态和生命周期 |
| 机会正文、交流与审核 | 已集成 NodeBB 的插件/原生 API | 结构化机会字段和入口，原生正文引用 |
| 联系与站内沟通 | 已集成 Nakama、联系人同意 | 业务关联，不旁路联系人授权 |
| 提醒、到期与故障恢复 | 已集成 pg-boss/事务outbox | 有界任务、去重和失败管理 |
| 向量与接待 | 已集成 pgvector、BGE、可选Hermes | 会话隔离与当前发布源；私人资料不自动入库 |
| 管理及空间 UI | React-admin、Three.js 和既有原生页面 | 业务编辑、审核、点位卡片和统一权限 |

NodeBB 官方插件与 API 已具备扩展点，PostgreSQL 提供索引和结构化事务能力，优先在已有开源基础上扩展学校领域。CiviCRM 或独立预约平台会另外引入身份/联系人/部署主干，本轮不整包接入；预约的时间/容量规则复用现有事务设计。若后续需要外部日历同步，另做固定版本适配和实测，不把当前接口夹具当作已集成第三方平台。

选型依据：[NodeBB插件](https://docs.nodebb.org/development/plugins/)、[NodeBB核心库](https://docs.nodebb.org/development/plugins/core-libraries/)、[PostgreSQL文本查询](https://www.postgresql.org/docs/current/functions-textsearch.html)。固定依赖沿用包内锁文件，本轮不为这些业务再部署一套账号、论坛或向量系统。

## 7. 开发顺序与退出条件

1. 接待会话：新增/继续/切换、用户间与学校/Agent间隔离、并发顺序、重启恢复、导出、删除/到期和旧回执拒绝；后台期限设置。没有配置真实模型时单列模拟 provider，不冒称实跑模型。
2. 校友目录：自愿登记、审核、筛选、退出/撤权、本人编辑和管理员管理，页面与锚点一致。
3. 支持预约：时段/容量、申请确认取消、并发不超卖、参与者隐私和通知；后台能管理。
4. 机会模块：原生正文/审核和结构化元数据联动，截止/撤回即时失效、筛选/点位及管理。
5. 交付：新迁移、新隔离测试命名空间、对应后端正反用例、浏览器角色流程/窄屏/场景点位、备份恢复覆盖新增表，封装新版本并保留旧包。所有专属应用/浏览器/模型工作进程测试后关闭。

本计划描述获准的待实现工作，不能作为这些新增功能已通过的证明。测试记录必须补真实结果，实际学校运营、身份核验、导师服务和雇主真实性仍须人工确认。
