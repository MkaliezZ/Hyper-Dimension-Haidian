# 接入学校自有人物美术：Agent执行清单

> 执行前先读 [统一开发手册](../DEVELOPMENT-MANUAL.md) 与 [AGENTS](../AGENTS.md)。本文是分项清单；当前版本、运行模式、验证和打包以统一手册为准，保留旧包与用户数据。

先读 AGENTS.md、docs/M2.md、assets/avatars/catalog.json、src/avatar/catalog-m2.mjs/model-m2.mjs。本任务为可运行人物与素材扩展，不涉及小游戏或经济系统。

1. 先读 docs/AVATAR-SCHOOL-ART.md。Base负责简单部件编辑、动作、权限和存档，学校负责美术。现有原创人物仅作可运行占位与兼容性样例；不要把增加样例部件数量作为默认开发目标。询问或复用学校风格；保留已保存配方、旧素材、部件ID及版本。
2. 默认使用学校有授权的素材或新增原创几何。不抓取不明授权人物；登记作者、来源、商用/改作/分发许可、版本、文件摘要和骨架兼容性。
3. 先选一个部件槽位做样例。沿用 campus-humanoid-1 的骨骼/米制坐标；增加外部柔性蒙皮或任意VRM导入属于新适配工作，不能只放文件就称兼容。
4. 部件、目录、骨架或生成器有实际变化时建立新版本与显式迁移；缺失/不兼容部件明确提示，不能静默替换存档。保存原模型库以便旧配方恢复。
5. 再生成模型与目录，验证SHA-256、站立/行走/挥手、身体与衣服穿插、头发与帽领兼容性；遵守22k三角面/90批次/1.6MB预算。
6. 在独立测试库编辑、保存、退出登录、第二浏览器恢复、重启/备份恢复。再进入空间走动和使用道具，确认实际模型与保存摘要一致。
7. 交付源码、生成器、素材、许可、目录、截图和迁移验证。原包与用户数据保留；学校最终美术审定、实际服务器容量不以自动截图代替。

给美术生成Agent的首轮提示可使用：

> 为【学校/社团】设计【风格】的人物外观，先制作正面、侧面、背面参考及【一个槽位】的样件。沿用本包固定骨架和米制坐标，读取实际骨骼节点与部件目录后制作；保持简单部件搭配，不做精细捏脸、布料模拟或复杂表情。提交可编辑源文件、授权说明、模型/贴图、比例与面数报告。生成图片只算设计参考，不能冒充已绑定骨架的可运行模型；后续由开发Agent完成接入、动作和旧存档验证。
