# 给 Agent 的美术美化清单：从结构原型到可展示的学校空间

> 执行前先读 [统一开发手册](../DEVELOPMENT-MANUAL.md) 与 [AGENTS](../AGENTS.md)。本文是分项清单；当前版本、运行模式、验证和打包以统一手册为准，保留旧包与用户数据。

这是默认搭建流程的一部分。用户不用知道“还要发哪段提示词”：基础场景跑通后，Agent 主动说明当前处于结构原型阶段，提出下一步视觉升级；收到“帮我美化/做漂亮一点”等请求时自行执行本清单。

## 先对普通用户这样说

> 现在房间和路线已经跑通，这一版主要验证结构。下一步我可以帮你把它做得更适合展示：统一校园风格，补地面、植物、桌椅和指示牌，再整理灯光、展板与接待区。你可以给我学校照片或喜欢的参考图；没有参考，我可以先按清爽的校园风做一个入口和房间样例。

有明确风格或参考图时直接采用，不重复问。没有方向时，用下面三个容易理解的选项引导，通常只问一次；用户让你决定时采用“校园清爽”并说明选择。

| 方向     | 看起来是什么感觉                     | 优先素材                                       |
| -------- | ------------------------------------ | ---------------------------------------------- |
| 校园清爽 | 明亮、自然、整洁，适合学校日常展示   | 浅色墙地、绿色植物、木色桌椅、清晰导览牌       |
| 温暖手绘 | 亲切、有社团与学生作品气息           | 低对比手绘纹理、软轮廓家具、公告栏、原创小摆件 |
| 轻科幻   | 有数字校园和科技展览感，保持文字易读 | 克制的蓝绿点缀、简洁展台、柔和发光标识、信息屏 |

2.5D 是可选择的表现方式，不等于只能换几张贴图。根据包内引擎和素材条件，选择协调的斜视角、billboard、简化 GLB 或 3D 剖切；说明实际采用了什么，不把三维体块渲染声称为完成了另一套引擎。

## Agent 执行步骤

1. **读现状再决定**：读 AGENTS.md、项目 HANDOFF/MODELING-NOTES、docs/EXTENSIONS.md。打开实际场景，识别当前入口、重要房间、展项、导航和接待区；保留原有截图、几何、ID、数据和可通行关系。
2. **建立一页视觉基准**：在项目写 ART-DIRECTION.md，记录选定风格、3–5 个主色、墙/地/家具材料、光照感觉、相机视角、标识字体与尺度、需要的素材，以及用户已给的参考。不要让每栋楼、每件家具各用一套画风。
3. **先做有代表性的小范围**：用一个入口和一个房间建立材质、植物、家具、指示牌、展板与灯光样例，展示与原型的差异。未收到新的方向调整时，按同一基准推进其余场景，不逐房间重复索要确认。
4. **补齐素材而非只改颜色**：优先使用校方获准照片、校徽和作品；无现成资料时制作明确标注的原创占位素材。可用图片生成工具制作协调的地面纹理、植物、导览标牌、家具或 2.5D 贴图；也可用代码生成 SVG/图案或参数化 GLB。根据实际工具能力执行，没有生成图片时不得声称已生成图片。记录素材来源、用途和可公开范围。
5. **落入可运行项目**：按 assets/exhibits/scene.artwork 的现有接口接图片或 GLB，校准尺寸、锚点、朝向、透明边缘和 footprint；避免巨大的 billboard 遮住房间和导览。优先在学校包管理内容；需要新主题能力时做通用、兼容的扩展，不把一所学校写死在 Base 核心。
6. **整理整体视觉层次**：明确入口焦点、房间标识与主路径，减少杂乱；统一材料粗糙度、阴影与灯光色温，避免发白、过暗或高饱和拼贴。协调前端标题、按钮、接待区和展板的字体、间距、对比度，使用户知道能点哪里、如何进入房间。
7. **保持功能**：家具和植物的可见占地要与碰撞/寻路一致；重点标牌可读，门和楼梯不被装饰堵住。建模数据、模型和导航仍来自同一份几何源，不用视觉覆盖掩盖通行错误。
8. **用实际画面收尾**：至少提供一张总览、一张重要房间和一张窄屏效果图，并验证入口、房间、跨层、返回与接待仍可用。窄屏自动浏览器检查只记录为视口检查，不冒充物理手机/多设备验收。保存前后对比、ART-DIRECTION.md、素材清单、实际验证及待补项。

## 完成标准

- 不再只有默认体块：入口/重要房间有协调的材料、家具或植物、导览标识和可用展项。
- 整个空间使用同一套视觉基准，文字和交互能读懂，视角能看清主要内容。
- 新素材能由项目数据重建，已有 ID、存档、权限与通行不被破坏。
- 原创占位、概念推定和校方真实内容区分清楚；没有把未生成素材或未做验证写为已完成。
- 交接明确当前处于“结构原型 / 视觉升级 / 待校方素材 / 可展示候选”的哪一步，以及下一件用户最容易提供的材料。

用户若只想先做原型或暂缓美化，记录下一步即可；用户要求完整可展示版本时，美化阶段应纳入交付，不把白模当最终视觉成果。
